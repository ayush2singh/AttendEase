# REVIEW.md

Defects identified in the starter `app/main.py` (helpers, endpoints, and data modeling) evaluated against `openapi.yaml` (rules R1–R10) and `DATA_MODEL.md`.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–37) | **Premature integer truncation before grace check:** Integer division truncates seconds to whole minutes before evaluating `if minutes > 10`. Per rule R2, an employee is late only if strictly more than 10 minutes past shift start (i.e. > 600s), but once late, the penalty is elapsed minutes since `shift_start`. With starter code, punching in at 09:40:01 (601 seconds) yields `minutes = 10`, failing `> 10` and returning `0` instead of `10`. | Punch in at 09:40:01 for a 09:30:00 shift. Expected `late_minutes: 10`, but received `0`. | Truncate timestamps to whole seconds (R1), compute elapsed seconds `elapsed_sec = (punch_in - shift_start).total_seconds()`. If `elapsed_sec > 600`, return `int(elapsed_sec // 60)`, else return `0`. |
| 2 | `compute_late_minutes` (lines 33–37) | **Timezone and overnight shift date dislocation:** `punch_in.replace(hour=h, minute=m)` blindly replaces hour and minute on `punch_in`. If `punch_in` is in UTC or naive, or for an overnight shift (e.g. 22:00–06:00) where punch-in occurs after midnight (e.g. 00:15 IST), replacing hour sets shift start to 22:00 of the *current* day, yielding negative elapsed time (-21.75 hours) instead of +135 minutes late. | Night shift employee (22:00–06:00) punching in at 00:15 IST receives `late_minutes: 0` instead of `135`. | Parse `shift_start` anchored to the record's IST attendance date `date_str` in `UTC+05:30`. |
| 3 | `compute_work_hours` (lines 40–41) | **Banker's rounding instead of half-up rounding:** Uses Python's built-in `round()`, which performs round-half-to-even (Banker's rounding). Rule R4 and R8 explicitly mandate "rounded to 2 decimals half-up (not banker's rounding, not float rounding)". | A work duration of 2.555 hours rounds down to `2.55` with `round()`, whereas half-up rounding requires `2.56`. | Compute duration via `Decimal` and apply `ROUND_HALF_UP`: `Decimal(str(seconds / 3600)).quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)`. |
| 4 | `compute_work_hours` (lines 40–41) | **Sub-second precision and offset awareness mismatch:** Does not truncate instants to whole seconds prior to calculation (violating R1). Also fails with `TypeError` if `punch_in` or `punch_out` have mixed timezone awareness (one naive from MongoDB, one aware). | Subtracting an aware datetime from a naive datetime throws `TypeError: can't subtract offset-naive and offset-aware datetimes`. | Truncate both instants to integer seconds/milliseconds and convert to UTC/epoch seconds before subtracting. |
| 5 | `compute_overtime` (lines 44–47) | **Missing 30-minute threshold check:** Rule R3 specifies `overtime_minutes` = whole minutes (floor) between `shift_end` and `punch_out`, counted *only when that is >= 30; otherwise 0*. Starter code returns any positive minute delta without verifying the 30-minute minimum threshold. | Punching out 15 minutes after `shift_end` awards `15` minutes overtime instead of `0`. | Calculate `diff_minutes = int((punch_out - end).total_seconds() // 60)`. If `diff_minutes >= 30`, return `diff_minutes`, else return `0`. |
| 6 | `compute_overtime` (lines 44–47) | **Overnight shift end set to wrong calendar date:** Sets `end = datetime.fromisoformat(date_str).replace(hour=h, minute=m, tzinfo=IST)`. In an overnight shift (e.g. 22:00–06:00), `shift_end` occurs on the *next* day (`date_str + 1 day`). Setting `end` to `date_str` places shift end 24 hours too early (16 hours prior to shift start), generating over 1,400 minutes of erroneous overtime. | Overnight shift worker punching out at 06:10 IST receives ~1,450 overtime minutes instead of `0` (since 10 min < 30 min). | Inspect shift definition; if `shift_end <= shift_start`, add `timedelta(days=1)` to `end`. |
| 7 | `create_employee` (lines 78–85) | **`created_at` serialization format mismatch:** `doc["created_at"] = datetime.now()` stores and returns a Python `datetime` object. The OpenAPI contract defines `created_at` as `EpochMillis` (an integer timestamp representing epoch milliseconds). | Calling `POST /employees` returns an ISO string or fails contract validation expecting an integer millisecond timestamp. | Set `doc["created_at"] = int(datetime.now(timezone.utc).timestamp() * 1000)`. |
| 8 | `list_employees` (lines 88–96) | **Off-by-one pagination skipping first page:** Line 93 sets `skip = page * page_size`. Because `page` starts at 1 (R10), requesting `page=1, page_size=20` evaluates to `skip = 20`, completely skipping the first 20 employees and serving page 2. | Calling `GET /employees?page=1&page_size=20` returns employees 21 to 40 instead of employees 1 to 20. | Compute pagination offset using `skip = (page - 1) * page_size`. Validate `page >= 1` and `1 <= page_size <= 100`. |
| 9 | `list_employees` (lines 88–96) | **Total count ignores query filter:** Line 94 sets `total = db.employees.count_documents({})`, which counts the entire collection without applying the department filter `q`. Rule R10 requires: `total always reflects the applied filters`. | Querying `GET /employees?department=Sales` returns Sales employees, but `total` reports total company headcount across all departments. | Execute `total = db.employees.count_documents(q)`. |
| 10 | `punch_in` (lines 99–121) | **Unhandled missing employee returns 500 instead of 404:** Line 101 executes `emp = db.employees.find_one({"emp_code": body.emp_code})`. When an employee does not exist, `emp` is `None`. Line 113 then evaluates `emp["shift_start"]`, triggering `TypeError: 'NoneType' object is not subscriptable` and returning HTTP 500. | Punching in with an unregistered employee code returns a 500 Internal Server Error instead of the specified 404. | Add check: `if not emp: raise HTTPException(404, "Employee not found")`. |
| 11 | `punch_in` (lines 99–121) | **Overnight shift punch-in assigned wrong attendance date:** Line 103 sets `d = ts.date().isoformat()`. Per Rule R1, for overnight shifts (`shift_end <= shift_start`), a punch-in whose IST time is *earlier than* `shift_end` belongs to the shift that started the previous calendar day. | An employee on a 22:00–06:00 shift punching in at 00:15 IST is logged under today's date instead of yesterday's shift start date. | Convert timestamp to IST. The OpenAPI spec mandates that the database reject duplicate punches with a duplicate key (409). | Sending two parallel punch-in requests simultaneously creates duplicate attendance records in MongoDB. | Create a unique compound index `{"emp_code": 1, "date": 1}` in MongoDB, catch `pymongo.errors.DuplicateKeyError`, and return HTTP 409. |

FastAPI serializes `ts` as an ISO-8601 string, violating the OpenAPI schema which requires integer epoch milliseconds. | Client validation fails because `punch_in` is an ISO string instead of an integer count of milliseconds. | Convert BSON/Python datetimes to integer epoch milliseconds before returning API responses. |

Spec warns: "Must stay fast on a collection of ~100,000 records; do not load the collection into memory." | High query latency and out-of-memory errors on large collections (~100,000 records). | Use MongoDB server-side cursor operations: `.sort(...).skip(skip).limit(page_size)`. |

---

## Decided Not a Defect

1. **`GET /health` returning `{"status": "ok"}`:**
   - **Evaluated:** Checked whether the endpoint needed to verify active MongoDB connectivity or return system metrics.
   - **Decision:** Not a defect. The OpenAPI contract defines `GET /health` with a minimal 200 OK schema (`status: ok`) intended strictly as a lightweight liveness check.

2. **Default shift hours in `EmployeeIn` (`shift_start: "09:30"`, `shift_end: "18:30"`):**
   - **Evaluated:** Checked if shift parameters should always be strictly mandatory without defaults.
   - **Decision:** Not a defect. 09:30 to 18:30 represents the standard office day shift across the business specifications, and providing these defaults simplifies onboarding without violating schema requirements.

3. **Storing `date` as ISO string `"YYYY-MM-DD"`:**
   - **Evaluated:** Checked if `date` should be stored as a BSON Date object in MongoDB.
   - **Decision:** Not a defect. `DATA_MODEL.md` explicitly defines the schema as `date: string "YYYY-MM-DD"` representing the IST attendance calendar day (R1), and sample documents confirm this representation.

4. **Initializing `history: []` at punch-in:**
   - **Evaluated:** Checked whether punch-in and punch-out lifecycle events should generate entries in `history`.
   - **Decision:** Not a defect. Section 4 of `DATA_MODEL.md` explicitly specifies that `history` records **manual corrections only** (regularizations) via `PATCH /attendance/{emp_code}/{date}`. Original punch-in and punch-out events must never write to `history`.

5. **Rejecting duplicate punch-in with HTTP 409 Conflict:**
   - **Evaluated:** Checked whether a second punch-in should update or create a split shift.
   - **Decision:** Not a defect. Business rules allow exactly one attendance record per employee per attendance date. A subsequent punch-in on the same date is explicitly specified in `openapi.yaml` to return HTTP 409.
